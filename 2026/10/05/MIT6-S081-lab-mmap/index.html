MIT6-S081-lab-mmap

Author: Gazettm Date: 十月 5, 2026  16:48:23 Category: OS

前言

这个 lab 主要让我们实现 mmap 和 munmap 两个系统调用：把文件的内容映射进进程的地址空间，之后像访问数组一样读写它，需要的时候再写回文件。实现用的是 lazy 策略，也就是 mmap 本身既不读文件也不分配内存，等用户真的读到或者写到那一页、触发了缺页中断，才把对应的页填上。测试集传的长度都是按页对齐的，所以这里没有做对齐处理。

设计思考

通过test代码我们可以看到如下的类似代码

这一行说明 mmap 返回的是虚拟地址。六个参数分别是：第一个是”我希望映射到哪个地址”，传 0 表示让内核自己挑一段空闲的（本 lab 只支持这一种，原因见最后一节）；第二个是要映射多少字节；第三个 prot 是”我要对这块内存做什么”，取值是 PROT_READ / PROT_WRITE；第四个 flags 是”改动要不要落到文件上”，MAP_PRIVATE 表示不写回（改动只留在内存里），MAP_SHARED 表示要写回；第五个是文件描述符，指定映射哪个文件；第六个是文件内的起始偏移量。

我们为什么需要lazy策略？如果我们不进行lazy操作，那么读一个文件之后需要将这个文件的所有部分都写入内存，而lazy操作可以让我们一页一页的读写，如果我们只访问了这个文件的一小部分，那么带来的是巨大的性能提升。但是这同样带给我们挑战，因为我们必须处理pagefault的问题，我们需要在读写缺失的时候再把缺少的页从文件映射进内存里面。

我们需要一个结构体来记录”哪一段虚拟地址对应哪个文件的哪一部分”，因为缺页的时候要靠它找到对应的文件、把内容读进主存。这里有个关键点：记录的是 struct file * 而不是 fd 号。因为 fd 会被 close，而且 fd 号之后会被新的 open 复用——test mmap private 里就是 mmap 完立刻 close(fd)，可映射还得继续能用。所以每条映射必须自己抓一份文件结构体、用 filedup 让它活着。于是我们定义结构体 vma，存下面这些东西，并在 proc 结构体里放一个 vma 数组，大小是 16。另外要记住：进程槽位是复用的，所以这个数组必须在 allocproc 里清空，否则新进程会看到上一个进程留下的登记。

这里还有一个问题：把文件映射到哪？用户虚拟地址的最上面两页是 TRAMPOLINE 和 TRAPFRAME；下面依次是用户栈、heap、data/text。注意 p->sz 是”这个进程占用的内存到哪儿为止”这个边界值，用户栈就在 [0, p->sz) 的最高处（exec 分配的两页，其中低的那页清掉 PTE_U 当 guard page）。我们显然不能把映射塞进栈里面，所以选 p->sz 到 TRAPFRAME 之间那片空地，刚好把这些空闲的地址用起来。

这里还有一个问题：映射了多个文件之后再解除映射，会出现空洞。例如先在前面一段地址映射文件 A，再在后面一段映射文件 B，然后解除 A 的映射，A 那一段就成了空洞。我的做法是不回头：每次新映射都取”所有已有映射里最大的结束地址”当起点，于是空洞永远不会被复用。敢这么做的理由是，从 p->sz 到 TRAPFRAME 之间有大约 256GB 的余地（整个用户地址空间的上界 MAXVA 是 2 的 38 次方），而这个 lab 最多只有 16 条映射，浪费几个洞完全无所谓；换来的是”新映射一定在所有已有映射之上”这个自明的性质，不用再去论证区域之间会不会重叠。真实系统不会这么干——它们要复用空洞，否则一个长期运行、反复 mmap/munmap 的进程，地址空间会被慢慢吃掉。

于是整个过程是：mmap 在 VMA 表里登记一条记录并返回一个虚拟地址；用户对这个地址读写；因为懒策略，那些页还不在内存里，于是触发缺页、进入 mmapfault。

缺页处理里最关键的一步，是理解”同一张物理页、两套页表”。kalloc() 给我的是一页物理内存，内核页表把整块 RAM 直接映射（内核虚拟地址等于物理地址），所以内核拿这个地址直接 memset、readi 都没问题；接着 mappages 做的事是”在用户页表里再记一条：这个虚拟地址也指向同一张物理页”。这就是多对一——一张物理页，两套页表都能到达它。之后用户读写那个虚拟地址，走用户页表，落到同一张页上；内核那条直接映射一直存在，但它不算”引用”，所以释放的时候只 kfree 一次。

代码

mmap

注意这里的几处判断。空槽的判据是 file == 0：一个正在使用的映射一定带着文件，所以 file 为 0 就是空槽。这也要求所有遍历 VMA 表的地方都先判断 file（mmap 找空槽、munmap 找目标、缺页找目标、exit 清理、fork 复制，一共五处），否则会拿残留的地址去比较。前面提过，这个数组还必须在 allocproc 里清干净。

mmapfault

这个函数在缺页时被调用：usertrap 里判断 r_scause() 是 13（读缺页，load page fault）还是 15（写缺页，store page fault），是的话就调它。

这里有个我之前的错误：页表项的权限必须一次性按 VMA 里的 prot 算全（PROT_READ 给 PTE_R、PROT_WRITE 给 PTE_W）。我一开始是按 scause 推的——读缺页就只给 PTE_R——结果用户接着写同一页时又缺页，处理函数对着一个已经映射好的页再调一次 mappages，直接 panic("mappages: remap")。scause 只用来判断”这次访问合不合法”，不用来决定权限。

vmaunmap

辅助函数：把一段区域里的映射释放掉，需要写回的先写回。sys_munmap 和 exit 共用它。

有两个细节：一是每一页都要先用 walkaddr 判断”这一页在不在”（返回 0 就是从来没被访问过；懒映射下这种页一定有，直接对它调 uvmunmap 会 panic("uvmunmap: not mapped")）；二是写回的条件是 MAP_SHARED 并且 prot 里带 PROT_WRITE（只读的共享映射没必要写回，而且那个文件可能本来就是只读打开的）。

munmap

用于解除映射，第一个参数是起始地址、第二个参数是长度。mmaptest 只会从两端拆（正好整段、拆掉开头一段、拆掉末尾一段），不会在中间挖洞，所以下面三个分支就够了。另外注意 vmaunmap 的参数是值传递，它不会改到这里这个 uaddr，所以后面那三个判断可以直接用原值。

其他

还有三处不贴代码，但值得记下来。

fork：把父进程在用的 VMA 条目复制给子进程，并且对每个复制过去的 struct file * 调一次 filedup（子进程要自己持一份文件引用）。页表不用管——uvmcopy 已经把”已经映射好的页”复制过去了；那些还没被访问过的页，让子进程自己缺页去填就行。

exit：把进程还挂着的映射按 munmap 的方式收尾，该写回的写回、该释放的物理页释放、最后 fileclose。这一步必须在 proc_freepagetable 之前做完，因为那之后页表就没了。

trap.c：在 usertrap 里加一个和系统调用分支并列的 else if，判断 r_scause() 是不是 13 或 15，是的话调用 mmapfault，返回值小于 0 就把进程标记成 killed。

其他思考

为什么这里的mmap第一个参数为0？

mmap 的第一个参数在真实 API 里是”我希望放在哪个地址”（0 = 随便挑；非 0 = 提示；非 0 + MAP_FIXED = 强制）。这个 lab 官方明确只要求 0 这一种。所以传了非 0 就返回失败——显式失败好过默默忽略（默默忽略会得到”映射成功了但地址和你要求的不一样”这种静默错误）。

这里的权限位是怎么回事？

在 sys_mmap 里做的这次检查，问的是”这个文件允许建立这样一组映射吗”，依据是 struct file 里的 readable / writable（也就是这个文件当初是用什么模式打开的）。要求读，文件就必须可读；要求写、并且是 MAP_SHARED，文件就必须可写——因为”改这块内存”的语义就是”改文件”。这里有个容易混的地方：要求写但 flags 是 MAP_PRIVATE 时，文件可不可写都不管，改动只落在进程自己那份私有副本上，文件从头到尾没被碰过。这两条正好是 test mmap private（只读文件 + 可写 + private，要成功）和 test mmap read-only（只读文件 + 可写 + shared，必须失败）的正反面。失败时返回的是 -1（用户侧就是 MAP_FAILED），不是 0。

在 mmapfault 里还有一次检查，问的是”这次访问被这条映射允许吗”，依据是 VMA 里的 prot 加上 r_scause() 给出的访问类型：读缺页要求 prot 里有 PROT_READ，写缺页要求有 PROT_WRITE，不符合就返回 -1，由 usertrap 把进程标记成 killed（也就是结束这个进程）。

两次检查看起来重复，其实判据不同：sys_mmap 那次比的是”用户想要什么”和”文件能干什么”；mmapfault 那次比的是”这次访问想干什么”和”这条映射允许什么”。两次都不能省——少了后一次，往只读映射里写时会对已经映射的页再 mappages（就是上面那个 remap panic）；少了前一次，test mmap read-only 检查的 mmap 返回值就不对了。
