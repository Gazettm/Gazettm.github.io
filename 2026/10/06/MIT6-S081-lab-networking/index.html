MIT6-S081-lab-networking

Author: Gazettm Date: 十月 6, 2026  16:20:32 Category: OS

前言

测试完毕，如下：

networking

这个实验要我们写两个函数，一个是e1000_recv，一个是e1000_transmit。一个用于接收网络信息，一个用于发送网络信息。

e1000_recv：网络进入e1000网卡，通过DMA传送到内存中，接下来我们需要使用这个函数从内存里面读取信息。

e1000_transmit：我们通过这个函数将信息（包）写入内存里面，之后通过DMA写入e1000网卡，然后网卡通过网络发送出去。

这里有 tx_ring 和 rx_ring 两个环，前者用于发送、后者用于接收。环上各 16 个格子（描述符），写满就绕回第 0 格。

先看一个格子里装了什么：

发送环的两根指针：TDH 是网卡已经发到哪儿，TDT 是驱动下一个要填的格子。驱动只操作尾指针，头指针是给网卡用的、看都不用看。这里有点像工厂的流水线：两个工人站在传送带两端，中间是已经放上去、还没被处理掉的包。

接收环是反过来的：网卡往环里写包（写到哪儿由 RDH 记录），驱动从 RDT+1 开始取包，RDT 是”驱动已经还给网卡的空缓冲到哪儿”这条线。所以两个环的方向正好相反——发送是驱动往前放，接收是驱动往前取。

把整条路连起来看：

代码

e1000_transmit

这里我们先获取锁，避免多个进程同时改这个环。然后把尾指针 regs[E1000_TDT] 读进 index——它指向”驱动下一个要填的格子”。（#define E1000_TDT (0x03818/4) /* TX Descriptor Tail - RW */）

接着判断这一格是不是 done：看它 status 里的 DD 位有没有置位。没置位说明网卡还在发这一格上一轮的包，此时不能碰它，只能释放锁并返回 -1。返回 -1 之后那块 mbuf 由调用者释放——net.c 里的调用点就是 if (e1000_transmit(m)) { mbuffree(m); }。

DD 置位了才可以复用这一格，这时顺便把这一格上一次用的 mbuf 释放掉（tx_mbufs[index]）。这是它唯一安全的释放时机：DD 置位才代表网卡真的把那个包发出去了。然后把这次的 m 记进账本，填好描述符的 addr、length 和 cmd。

cmd 这两位都要设：EOP 表示”这是这个包的最后一个分片，可以发了”，RS 表示”发完请把状态写回描述符”——不设 RS，网卡就不会置 DD，下一轮就会把这一格永远当成”还在发”，整条发送路径直接死掉。

最后一步是把 TDT 自增取余写回寄存器。这个写动作本身就是通知网卡”这一格交给你了”；顺序不能反——先把描述符内容写好，最后才动 TDT，否则网卡可能看到尾指针前移了、去读一个还没填好的描述符。

e1000_recv

接收的入口在中断里：网卡收到包之后发中断，e1000_intr() 先读 ICR 把中断清掉，然后调用这个函数。

首先要明白环上可能攒着好几个包：一次中断可能对应环上排了好几个（网卡连着 DMA 了好几次），所以这里用 while 循环，一直处理到某一格的 DD 没置位为止。只处理一个的话，剩下的包要等下一次中断，而中断不一定会马上再来。

每一轮做四件事：

  1. 算出下一个可能有包的格子：(RDT+1)%RX_RING_SIZE。RDT 是”驱动已经还给网卡的空缓冲到哪儿”，所以它的下一格就是网卡最可能刚放好包的那一格。
  2. 看这一格的 DD。没置位就是没有新包，直接返回。
  3. 把描述符里报告的包长抄到 mbuf 上（rx_mbufs[index]->len = rx_ring[index].length），然后 net_rx() 把它交给网络栈。长度能直接当包长用，是因为 e1000_init 里把接收控制寄存器 RCTL 的 SECRC 位设上了——网卡已经把以太网尾部那 4 字节 CRC 剥掉了。这一步之后这块 mbuf 就归网络栈了，代码里再没碰它。
  4. 立刻补一块新的 mbuf 写回描述符的 addr，把 status 清 0，再把 RDT 推到这一格。这三件都不能省：不补新 mbuf，网卡下一次 DMA 就会写进已经交给协议栈的那块内存里，表现为偶发数据损坏（最难查的一类）；不清 status，下一轮循环会把同一个包反复当成新包；不推 RDT，网卡就不知道这一格的空缓冲已经还回来了。

（补 mbuf 时如果 mbufalloc() 返回 0 就直接 panic，和 e1000_init 里对同样情况的处理保持一致。）

这个函数跑在中断上下文里，而它摸的 rx_ring / rx_mbufs / RDT 和发送路径的 tx_ring / tx_mbufs / TDT 完全不重叠，所以这里不需要加锁——锁只保护发送路径。
