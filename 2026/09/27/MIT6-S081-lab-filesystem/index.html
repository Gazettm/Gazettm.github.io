MIT6-S081-lab-filesystem

Author: Gazettm Date: 九月 27, 2026  21:07:38 Category: OS

前言

lab file-system相对来说比较简单，以下是分数：

Large files

xv6 的一个文件最大只有 268 块（≈268KB），因为 inode 里只有 12 个直接块号 + 1 个一级间接块号（一级间接块里再放 256 个块号）。我们需要让一个直接块号变为一个二级间接块号，这样最大能支持11个直接块+1个一级间接块（存256个块号，可以有256KB）+1个二级间接块（存256个一级间接块，可以有256*256KB），这样文件最大有65803块（65803KB）。

这个任务其实还是比较简单的，我们使用二级块的时候可以参考已经写好的一级块的格式来进行。

思考

为什么要把一个直接块号变成一个二级间接块，而不是再加一个？因为有两个约束卡着。一是磁盘上 struct dinode 的大小不能变，磁盘格式是既成事实，大小一变 IPB（一块里放几个 inode）就跟着变，mkfs 造出来的镜像和内核读的就对不上了（make 输出里那行 inode blocks 13 正好可以拿来验证）。二是既然 dinode 的 addrs[] 只能还是 13 个元素，内存里的 struct inode 也必须和它保持一致：11 个直接块 + 1 个一级间接块 + 1 个二级间接块，最后那个就是新加的。

另外有个很容易漏的地方：MAXFILE 这个宏得跟着改。writei() 里有一句 if(off + n > MAXFILE*BSIZE) return -1;，只把 NDIRECT 改成 11 而不动 MAXFILE，文件写到 267 块就写不进去了，症状和完全没改一模一样。改完还要 make clean 重建 fs.img，因为 fs.img 的 make 规则不依赖 fs.h，不 clean 会继续拿旧镜像跑。

代码

bmap

这里的逻辑很简单，每个文件都有自己的逻辑块号，bmap 做的事就是把这个逻辑块号翻译成磁盘块号。当 bn（逻辑块号）为 0 ~ 10，直接映射；11 ~ 266 走一级间接映射；267 ~ 65802 走二级间接映射（先除以 NINDIRECT 找到外层是第几个一级间接块，再取余找到那个块里的第几项）。二级间接这里要分配两层：外层块 → 内层的一级间接块 → 数据块，用到哪一层才分配哪一层，addr 就是 bmap 最终返回的磁盘块号。

itrunc

这个函数是把一个 inode 的所有映射都清空，所以三层（直接块、一级间接、二级间接）都要遍历一遍释放掉。它有两个调用点：一个是 iput() 里 nlink 归零的时候，也就是真正的删除文件；另一个是 sys_open() 里带 O_TRUNC 的时候，也就是重写一个已经存在的文件（inode 保留、内容清空）。逻辑照着一级间接那段仿写就行，很简单。

Symbolic links

任务2：给 xv6 加上符号链接（软链接），也就是实现 symlink(target, path) 系统调用 + 一个新的文件类型 T_SYMLINK + 一个新的 open 标志 O_NOFOLLOW，并且让 open 能顺着链接一路找下去（遇到环要报错）。这里主要是支持了一种新的文件类型，打开这个文件之后如果这个文件类型是一个T_SYMLINK类型，那么就读这个文件里写的内容，然后进行目录查找。这个一开始可能不知道有什么用，但关键要理解一点：符号链接本身就是一个普通的文件，只不过它的内容是一串路径字符串。它像一张便签，上面写着“去三楼找张三”——便签不是张三，便签上写错地址照样能贴上去，张三搬走了便签也还挂在墙上。所以 open(B) 的时候，内核只是把 B 的内容（那串路径）读出来，再按这个路径重新找一遍。

它和硬链接（link）的区别，正好就落在这几点上：

硬链接 符号链接
目录项指向 同一个 inode 一个新建的 inode，内容是路径字符串
目标必须存在吗 必须，link 要求文件已经存在 不需要，symlink 不检查 target
删掉目标之后 数据还在，另一个名字照样能读 链接还挂在那里，但 open 会失败
谁来跟随 不需要跟随，本来就是同一个文件 只有 open 跟随，link/unlink 不跟随

思考

为什么必须把 target 当成字符串存进文件内容，而不能在建链接的时候就把目标解析成 inode 号？因为 symlinktest 里有一条检查：删掉目标文件之后，open 这个链接必须失败。如果提前解析了，链接就带上硬链接的性质，删掉目标也照样能打开，这样就不对了。

O_NOFOLLOW 是干什么用的？带上它就是不跟随，直接打开链接这个文件本身，fstat 出来的 type 是 T_SYMLINK。管理链接的工具需要操作链接本身，而不是它指向的东西。

为什么“跟随”只能做在 open 里，不能加到 namei/namex 里？因为 link、unlink 这些系统调用也走 namei，一旦在这里跟随，它们就跟着跳过去了，而官方要求它们必须作用在链接本身。

环怎么检测？链接指向自己、或者互相指，顺着走下去永远到不了头。所以我们设置一个阈值：跟随深度超过一个阈值（比如 10）就返回错误。

代码

sys_symlink

这个就是我们新建的。有一个目标文件和一个路径，我们需要在路径创建一个新的T_SYMLINK类型文件，然后写入target目标文件的路径。

sys_open

这个则是这样写，跟随的逻辑放在“不需要创建”的那个 else 分支里。整体是一个循环，每一轮做四件事：先 namei 拿到 inode 再 ilock；然后判断要不要跟随，只要不是 T_SYMLINK 类型、或者带上了 O_NOFOLLOW，就 break 出去，这时候 ip 还是锁着的，后面那些 T_DIR、T_DEVICE 的检查直接拿它继续用；如果确定要跟随，就用 readi 把链接文件的内容读进 path（直接把 path 覆盖成目标路径，不用另开缓冲区），再 iunlockput 放掉当前的 inode，回到循环开头用新路径重新查一遍。

有两个细节值得说。一是为什么必须先 iunlockput 再去查新路径：手里这个 inode 还锁着的时候去 namei，万一目标路径又指回它自己，就变成自己等自己的锁。二是 tries 那个计数（上限 10）是用来防环的，每跟随一次加一，超过就报错返回。
