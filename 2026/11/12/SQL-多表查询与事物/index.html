SQL 多表查询与事务

多表关系

设计表结构时，可以根据数据之间的关系决定把外键放在哪张表里。

关系 例子 实现方式
一对多（多对一） 一个部门可以有多名员工，每名员工最多属于一个部门 在员工表中放部门编号，作为指向部门表主键的外键
多对多 一个学生可以选多门课，一门课也可以有多名学生 建立选课表，用两个外键分别引用学生和课程的主键，两列可以组成联合主键，防止重复选课
一对一 一个用户最多有一条详情记录，一条详情记录只属于一个用户 把基础信息和详情分开，详情表的用户编号同时作为主键和外键

多表查询

下面用部门表和员工表演示连接、联合查询和子查询。先选中一个练习数据库，再建表和插入数据。员工表的 dept_id 表示部门编号，manager_id 表示上级的员工编号。

INNER JOIN 内连接

内连接只返回满足连接条件的行。隐式写法在 FROM 里用逗号列出两张表，把连接条件放在 WHERE 里。显式写法用 INNER JOIN ... ON ...，其中 INNER 可以省略。两种写法都能查出有部门的员工及其部门名。

隐式写法省略连接条件时会得到笛卡尔积，也就是每名员工和每个部门各配对一次。这里有 6 名员工和 4 个部门，会得到 24 行。

LEFT JOIN 和 RIGHT JOIN 外连接

LEFT JOIN 保留左表的所有行，右表找不到匹配时用 NULL 补齐。下面的第一个查询保留 Frank，他的部门名是 NULL。

RIGHT JOIN 保留右表的所有行，左表找不到匹配时用 NULL 补齐。下面的第二个查询保留人事部，员工名是 NULL。两种写法中的 OUTER 都可以省略。

自连接

自连接就是把同一张表连接两次，需要给两边起不同的别名。例如，员工表中 e 代表员工，m 代表上级，通过 e.manager_id = m.id 找到上级的姓名。这里用左连接保留没有上级的员工。只查询有上级的员工时，可以换成内连接。

UNION 和 UNION ALL 联合查询

联合查询把多个 SELECT 的结果按行合并。每个查询选出的列数必须一致，对应位置的列按相同顺序写，类型应能相互兼容。

  • UNION ALL 保留所有行，包括重复行。
  • UNION 对合并结果按整行去重。

例如，把销售部员工和工资至少为 9000 的员工合并。Alice 和 Bob 同时满足两个条件，用 UNION ALL 时各出现两次，用 UNION 时各出现一次。

子查询

在一条 SQL 语句里嵌套另一条 SELECT，里面的查询就叫子查询。子查询可以用在 WHERE 中筛选数据、在 FROM 中提供一张查询结果表，或在 SELECT 中计算一个值。外层语句也可以是 INSERT、UPDATE 或 DELETE。

标量子查询

标量子查询返回一个值，可以用 =、<>、>、>=、<、<= 来比较。例如，先算出所有员工的平均工资，再查工资超过平均值的员工。

列子查询

列子查询返回一列，可以有多行。下面先查销售部和市场部的编号，再通过 IN 找到这两个部门的员工。

操作符 说明
IN 匹配子查询返回的任意一个值
NOT IN 排除子查询返回的值
ANY 与任意一个值比较成立即可，例如 > ANY (...)
SOME 与 ANY 等价
ALL 与每个值比较都成立，例如 > ALL (...)

MAX 会跳过 NULL，而 ALL 会逐项比较。例如，财务部的工资列如果包含 7000、8000 和 NULL，那么 9000 > MAX(...) 成立，9000 > ALL (...) 的结果是未知，在 WHERE 里会被过滤。用 NOT IN 时也要留意子查询里有没有 NULL。MySQL 的 ALL 子查询

行子查询

行子查询返回一行，可以包含多个值。可以把多个字段写成 (字段1, 字段2) 这样的元组，用 = 或 <> 比较。下面根据主键查到 Alice 的部门和工资，再找同部门、同工资的其他员工，结果是 Bob。

表子查询

表子查询可以返回多行多列。放在 FROM 中时，把它当成一张临时的查询结果表来用，并给它起一个别名。也可以用多列元组和 IN、NOT IN 来判断是否匹配其中的行。

事务

事务把一组操作作为一个整体提交或撤销。例如，转账需要同时完成付款账户扣款和收款账户加款。如果其中一步没完成，就应撤销这次转账已经做的修改。

开启、提交和回滚

  • START TRANSACTION; 或 BEGIN; 开启一个事务。
  • COMMIT; 提交当前事务，保存这次修改。
  • ROLLBACK; 回滚当前事务，撤销这次尚未提交的修改。

SELECT @@autocommit; 可以查看当前连接是否开启自动提交。值为 1 时，事务外的单条修改语句执行成功后会自动提交。用 SET @@autocommit = 0; 可以改为手动提交。练习后先提交或回滚，再按需要用 SET @@autocommit = 1; 恢复自动提交。也可以直接用 START TRANSACTION 开启一次事务，如下面的例子。

转账示例

先在练习数据库里准备两个账户，初始余额都是 1000 元。假设账户 1 向账户 2 转 100 元，两步都成功后提交，余额分别变为 900 元和 1100 元。

接着模拟第二次转账。扣款后发现收款账号填错，就回滚这次操作。最后两人的余额仍是 900 元和 1100 元。

事务的四大特性（ACID）

特性 说明
原子性（Atomicity） 事务中的操作要么全部生效，要么全部撤销
一致性（Consistency） 事务完成后，数据仍应符合约束和业务规则，例如转账前后两个账户的余额总和保持不变
隔离性（Isolation） 多个事务同时运行时，隔离级别决定它们能看到彼此的哪些修改
持久性（Durability） 事务成功提交后，保存的修改在数据库重启后仍然存在

事务隔离级别

并发事务中常见的三种读现象，可以用两个连接 A 和 B 来理解。

  • 脏读。A 读到了 B 尚未提交的修改，B 随后回滚了。
  • 不可重复读。A 在同一事务中两次查询同一条记录，B 在两次查询之间修改并提交了它，A 两次读到的值不同。
  • 幻读。A 在同一事务中按同一个条件查了两次，B 在两次查询之间插入或删除了符合条件的记录并提交，A 两次看到的记录集合不同。

下面按 SQL 标准列出各级别允许出现的现象，数据库的实际实现可以提供更强的隔离。SQL 标准的隔离级别对照表

隔离级别 脏读 不可重复读 幻读
READ UNCOMMITTED（读未提交） 可能 可能 可能
READ COMMITTED（读已提交） 避免 可能 可能
REPEATABLE READ（可重复读） 避免 避免 可能
SERIALIZABLE（串行化） 避免 避免 避免

MySQL 默认使用 REPEATABLE READ。可以查看当前连接的隔离级别，也可以用 SET SESSION 设置当前连接后续事务的隔离级别。换成 SET GLOBAL 会设置之后新连接的默认值。隔离更严格时，并发操作可能需要等待更久。MySQL 的 SET TRANSACTION 语句
