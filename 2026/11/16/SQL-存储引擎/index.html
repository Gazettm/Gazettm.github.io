SQL 存储引擎

存储引擎简介

存储引擎负责读写和组织表里的数据与索引。MySQL 可以给同一个数据库里的不同表指定不同的引擎。比如，员工表和部门表可以用支持外键的 InnoDB，一张随时可以重新生成的小型查询结果表可以用 MEMORY。

查看存储引擎

SHOW ENGINES 的结果里，Support 为 DEFAULT 表示可用且是默认引擎，为 YES 表示可用，为 NO 或 DISABLED 表示当前不可用。还可以看 Transactions 一列，确认引擎是否支持事务。

建表时指定存储引擎

在 CREATE TABLE 的右括号后写 ENGINE = 引擎名。普通表省略这一项时，MySQL 会使用当前连接的默认存储引擎。已经建好的表可以用 SHOW CREATE TABLE 查看实际使用的引擎。

表里的功能以 MySQL 8.0 为例。批量插入速度和资源占用还取决于索引数量、数据量和配置。

InnoDB

InnoDB 从 MySQL 5.5 起成为默认存储引擎。前面学的事务和外键都可以用在 InnoDB 表上。它支持行级锁，例如两个连接分别按主键更新不同的账户记录时，可以各自锁定对应的记录，减少相互等待。

表空间和文件

启用 innodb_file_per_table 时，默认给新建的 InnoDB 普通表分配独立表空间。例如，账户练习表通常对应一个 account_engine_demo.ibd 文件，里面保存表数据和索引。表也可以使用共享表空间。MySQL 8.0 用数据字典管理表结构，并把序列化后的元数据（SDI）存入 InnoDB 表空间。早期 MySQL 中单独保存表定义的 .frm 文件属于旧的存储方式。

截图里的逻辑结构可以按 表空间 → 段 → 区 → 页 → 行 来记。

层级 说明
表空间（Tablespace） 管理表数据和索引所占用的存储空间，可以由一个或多个文件提供
段（Segment） 管理索引等结构使用的页，可以按区分配空间，也可以先分配少量单独的页
区（Extent） 一组连续的页。默认页大小为 16 KiB，此时一个 1 MiB 的区包含 64 页
页（Page） InnoDB 读写和管理数据的基本单位，保存记录的页可以容纳多条记录
行（Row） 一条记录。截图里的 Trx id 记录修改该行的事务，Roll pointer 指向可用于找回旧版本的信息

例如，查询某个账户时，InnoDB 可以通过主键索引找到记录所在的页。一个页上还可能有其他账户的记录。

MyISAM

MyISAM 是早期 MySQL 的默认存储引擎。它使用表级锁，写入时的锁定范围覆盖整张表。它不支持事务回滚和外键，在一些以读取和追加为主、对并发写入要求较低的旧表中还能遇到。

MyISAM 把数据和索引放在不同的文件里。以课件中的图书表为例，tb_book.MYD 保存数据，tb_book.MYI 保存索引。MySQL 8.0 还会为表保存一个 .sdi 文件，里面是表结构等元数据。

MEMORY

MEMORY 表的记录和索引放在内存里。对于普通的 MEMORY 表，MySQL 重启后还能找到表定义，但表里的记录会清空。课件里提到的 .sdi 对应的是表结构等元数据。单表大小受 max_heap_table_size 限制，适合少量可以重新生成的数据。

MEMORY 默认用哈希索引，适合 WHERE id = 1 这种等值查询。需要用索引查找区间时，可以建 BTREE 索引。下面用一张小表保存可重新生成的部门人数统计。

怎么选择存储引擎

  • InnoDB 适合需要事务、外键或并发更新的业务表，例如订单表、账户表和员工表。一般的 MySQL 业务表也可以从默认的 InnoDB 开始。
  • MyISAM 常见于旧项目。维护以读和追加为主的旧表时，可以先确认它是否依赖 MyISAM 的现有行为，以及业务是否需要事务和外键。
  • MEMORY 适合体量小、可以重建的中间结果或缓存，例如上面的部门人数表。应用如果要把缓存放到 MySQL 之外，也可以用独立的 Redis 服务。补充笔记里提到的 MongoDB 属于文档数据库，选用它时还要考虑数据模型和查询需求。

已有表也能用 ALTER TABLE 表名 ENGINE = 引擎名; 更换引擎。更换时，MySQL 会重建表，需要先确认目标引擎支持表当前使用的功能。例如，带外键的 InnoDB 员工表就依赖外键检查。
